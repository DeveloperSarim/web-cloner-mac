How to save a whole website on a Mac

From a blank window to a copy that opens with the network off.

This walks through saving a complete website on a Mac, from installing the app to opening the copy with the network off. It takes about two minutes of your attention, then however long the site needs.

Save sites you own, sites that invite it, or pages you are allowed to archive. Leave the robots setting alone unless the site is yours.

  1. Install Web Cloner

    Download the disk image, drag the app onto Applications, then right-click it and choose Open the first time. If wget is missing, the app offers to install it.

  2. Type the address

    Put the site in the Address field. example.com is enough, the app fills in the rest. Starting from a section such as example.com/docs keeps the job inside that section.

  3. Choose where it lands

    Save to defaults to a WebCloner folder in Downloads. Press Choose to put it anywhere else. Each site gets its own folder named after the host.

  4. Pick the job

    Clone saves the site, Scan only lists what is there, Screenshot captures each page as an image. For an offline copy, leave it on Clone.

  5. Set how deep and how fast

    Whole site follows every internal link; one or two levels is plenty for a quick copy. Set Speed to Polite on a site you do not run, which adds a pause between requests and a rate cap.

  6. Press Start Cloning

    Pages appear in the list as they finish, with their size, and anything that fails is marked in red with the reason. Click a counter at the top to filter the list.

  7. Open it offline

    When it finishes, press Open Website, which opens index.html from your disk. Turn off Wi-Fi and reload to prove the copy is complete.

What ends up in the folder

<save folder>/ example.com/ the site, open index.html cdn.example.net/ images and fonts from the asset domain screenshots/ PNGs, if you ran that job sitemap.xml every page that was found

Making a job smaller or faster

  • Turn off images and media when you only want the words. HTML, CSS and JavaScript alone finish in a fraction of the time.
  • Limit the depth. Two levels covers most of what anyone actually reads on a blog or a documentation site.
  • Skip the heavy sections. In Advanced, leaving out a path such as /blog, or refusing PDFs, often removes most of the download. See the options.

When the copy does not look right

If it opens but looks unstyled, the stylesheet probably lives on another domain and the run was stopped early. Let the job finish, because the repair pass that fetches those files runs at the end.

If whole sections are missing, the site likely builds its pages in the browser with JavaScript. wget does not run JavaScript, so it saves the shell rather than the content. Use the Screenshot job for those sites: it renders each page in WebKit and gives you an image of what a visitor sees.

If nothing downloads at all, check that the address loads in a browser, then try Polite speed, which some servers are happier with.

Doing the same thing from a terminal

Every option in the app is a wget flag, and the Advanced panel has a button that copies the finished command. Paste it into a script when you want the same job to run on a schedule. The full mapping is here.
