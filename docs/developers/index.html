Options for developers

Each field is one wget flag, and the app will hand you the finished command.

Open Advanced in the Options card and the app stops guessing. Each field maps to exactly one wget flag, and a field you leave empty adds nothing to the command.

Two examples

Documentation only

Put /docs in Only these paths. Everything outside it is ignored, including the marketing pages and the blog that usually account for most of a download.

Everything except the archives

Put pdf in Skip file types and /tag/ in Skip URLs matching. Tag and category pages repeat content you already have, so dropping them often halves the job.

The command it builds

Copy wget command puts the exact invocation on your clipboard, ready for a terminal or a scheduled script. The app log hides any password; the copied command keeps it so the command still runs.

wget --recursive --level=inf --no-parent --convert-links --page-requisites \ --exclude-directories=/blog --reject-regex='\.pdf$' --quota=500m \ --directory-prefix=/Users/you/Downloads/WebCloner https://example.studio

What the app adds on top of wget

Two things happen that a bare command does not do.

The page list is parsed from wget's own output. Each URL becomes a row with a state and a size, assets are kept out of the way, and the counters filter the list.

The repair pass runs when a clone finishes. It reads the saved HTML and CSS, finds asset URLs that still point at another domain, downloads the ones you do not have yet, and rewrites each reference to the local file. It repeats once, so assets referenced by a stylesheet it just fetched are picked up too. That is the step that keeps images from going missing in an offline copy.

Reading the source

Argument building lives in one function, wgetArgs(), with tests beside it, so what the app runs is easy to check. The whole project is four Swift files. Read it on GitHub.
